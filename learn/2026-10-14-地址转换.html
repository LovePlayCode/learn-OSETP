第15章：机制：地址转换

学习日期：2026-10-14

📌 核心问题

每个进程都以为地址空间从 0 开始，怎么又快又安全地把它放到物理内存的别处？

第 13 章讲的是内存虚拟化要做成什么样（地址空间这个抽象），第 15 章讲的是底层怎么做到（地址转换这个机制）。

和 CPU 那条线的顺序一样：进程（抽象）→ 受限直接执行（机制）；地址空间（抽象）→ 地址转换（机制）。

目标仍然是三个：高效、控制（保护）、灵活。

🧱 概念分层：上下兄弟

今天三次层级错误后，自己理清的三层结构

第3层 目标 / 理念： 虚拟化（高效 + 控制） │ ┌───────────────┴───────────────┐ 第2层 具体机制： 受限直接执行 地址转换 ← 兄弟 │ │ └───────────────┬───────────────┘ 第1层 底层工具：用户态/内核态、特权指令、陷阱表、异常、 时钟中断、MMU（里面有 base/bounds 寄存器）……

注意：base 和 bounds 是 MMU 的组成部分，不是和 MMU 平级的东西。

⚙️ 基址 + 界限（A层）

两个寄存器各存什么

  • base：这个进程的地址空间，在物理内存里的起始地址（不是"空闲内存的起始地址"，分出去以后就不空闲了）
  • bounds：地址空间的大小（书里也提到存"结束物理地址"的变体，属于 C 层）

每次访存，硬件做的事（先检查，再加）

虚拟地址 VA │ ▼ ① 检查：0 ≤ VA < bounds ？ ← 比较运算，比的是虚拟地址 │ 否 → MMU 抛出异常 → 查陷阱表 → 非法内存处理程序 → OS 杀掉进程 │ 是 ▼ ② 转换：物理地址 = base + VA ← 加法运算，这一步本身就是"映射"

比较和加法都很简单，电路里一个周期就能做完，所以虽然每一次访存都要做，也不会拖慢程序。

例题（base = 16KB = 16384，bounds = 4KB = 4096）

虚拟地址检查结果
1KB = 10241024 < 4096物理地址 17408
30003000 < 4096物理地址 19384
44004400 ≥ 4096越界，抛异常，不做加法
40964096 ≥ 4096越界！最后一个合法地址是 4095

🤝 硬件和 OS 的分工（A层）

硬件负责（每次都发生）OS 负责（关键时刻出手）
  • MMU：每次访存检查 + 转换
  • 越界时抛出异常
  • 修改 base/bounds 是特权指令，用户态执行会抛异常
  • 出生：从空闲列表拿一块内存，标记为占用，设置 base/bounds
  • 死亡：把内存归还空闲列表
  • 换下 CPU：base/bounds 存进 PCB，换上下一个进程的
  • 做坏事：异常处理程序把进程杀掉
  • 开机时：初始化陷阱表

时钟中断时的上下文切换（自己填出来的时间线）

【硬件】把 A 的寄存器保存到 A 的内核栈 → 切到内核态 → 跳到时钟处理程序 【 OS 】把 A 的 base/bounds 存进 A 的 PCB → 从 B 的 PCB 取出 B 的 base/bounds 【硬件】从陷阱返回：恢复 B 的寄存器 → 切回用户态 → 跳到 B 的代码继续跑

内存是空分共享，A 被换下以后它的数据还留在内存里，所以切换时只换两个寄存器，不用搬内存。

两道防线，同一条路

  • 访问别人的内存：bounds 寄存器 → 异常 → 陷阱表 → OS
  • 偷改 base 寄存器：用户态 / 内核态 + 特权指令 → 异常 → 陷阱表 → OS

OS 不需要一直盯着进程，只要开机时把陷阱表准备好就行。

🔄 静态重定位 vs 动态重定位（B层）

静态重定位（软件）动态重定位（硬件 base/bounds）
什么时候改地址装入时一次性改写所有地址运行时每次访存由硬件转换
速度运行时不慢（这不是它的问题）加法 + 比较，很快
保护没有，可以随便访问任何地址bounds 拦截越界
搬家要把程序里每个地址重新算一遍停止 → 复制内存 → 改 PCB 里的 base、更新空闲列表 → 恢复运行

🔗 连接构建

横向：地址转换 vs 受限直接执行

  • 相似：每次都发生的事交给硬件做（快），OS 只在关键时刻出手（管得住）；都靠特权指令 + 异常 + 陷阱表防止进程乱来
  • 不同 1：CPU 是时分共享（轮流用），内存是空分共享（同时各占一块）
  • 不同 2：LDE 下程序大部分时间直接在 CPU 上跑，硬件很少介入；地址转换下硬件每一次访存都要工作

纵向：为什么这样设计？

  • 为什么虚拟地址从 0 开始？编译器不需要知道程序将来会被放在物理内存的哪个位置，编译一次，放哪里都能跑
  • 没有 bounds 会怎样？有 bug 的 A 悄悄写坏 B（甚至写坏 OS），10 分钟后 B 崩溃，程序员去查 B，很难找到真正的 bug。bounds 让错误在哪里发生就在哪里被拦下，它不只防坏人，也负责隔离
  • 替代方案？base/bounds 要求整个地址空间连续放，堆和栈中间没用的空间也占着物理内存（内部碎片）。改进：代码、堆、栈分开放，每块一对 base/bounds（共三对），用虚拟地址的高几位选择用哪一对 → 下一章《分段》

先写答案 + 一句思路，再展开对照。

练习 1：base = 0x3000（12288），limit = 472。下面 4 个虚拟地址，哪些合法？物理地址是多少？
VA 0: 0x000001ae (decimal: 430) VA 1: 0x00000109 (decimal: 265) VA 2: 0x0000020b (decimal: 523) VA 3: 0x000001d8 (decimal: 472)
参考答案

430 < 472，合法 → 12718（0x31AE）；265 合法 → 12553（0x3109）；523 ≥ 472，越界；472 = limit，越界（这就是坑，合法范围是 0～471）。

练习 2：进程会访问 120、87、929、512、3。limit 最小设成多少才能全部合法？
参考答案

930。最大的地址是 929，要满足 929 < limit，所以 limit 至少是 930（不是 929）。

练习 3：物理内存 16KB，地址空间（limit）1KB。base 最大设成多少，地址空间还能完整放进物理内存？
参考答案

16384 − 1024 = 15360（15KB）。地址空间最后一个字节的物理地址是 base + 1023，必须 ≤ 16383。

⌨️ 打字默写检查

合上资料，先在框里打出答案，再展开参考答案对照。脑子里默念不算哦～

1. base 和 bounds 各存什么？一次访存时，硬件先做什么、后做什么？
参考答案

base：这个进程的地址空间在物理内存里的起始地址；bounds：地址空间的大小。先检查 0 ≤ VA < bounds，越界就抛异常；合法再算 base + VA 得到物理地址。

2. OS 在哪四个时刻必须出手？每个时刻做什么？开机时还要提前准备什么？
参考答案

出生：从空闲列表拿内存、标记占用、设置 base/bounds；死亡：归还空闲列表；换下 CPU：base/bounds 存进 PCB，换上下一个进程的；做坏事：异常处理程序杀掉进程。开机时初始化陷阱表。

3. 时钟中断从 A 切到 B，按时间顺序，硬件和 OS 各做了什么？
参考答案

硬件：保存 A 的寄存器到内核栈、切内核态、跳到时钟处理程序。OS：A 的 base/bounds 存进 A 的 PCB，从 B 的 PCB 取出 B 的。硬件：从陷阱返回，恢复 B 的寄存器，切回用户态，跳到 B 的代码。

4. 静态重定位的两个真正问题是什么？动态重定位下搬家分几步？
参考答案

没有保护；装进内存后难以搬家（要重算每个地址）。动态重定位：停止进程 → 复制内存到新位置 → 改 PCB 里的 base、更新空闲列表 → 恢复运行。

5. 用户进程想访问别人的内存、想偷改 base 寄存器，分别被哪个底层工具拦住？
参考答案

访问别人的内存：bounds 寄存器 + 异常 + 陷阱表。偷改 base：用户态/内核态 + 特权指令（用户态执行特权指令也会抛异常）。

6. 地址转换和受限直接执行，哪里相似、哪里不同？
参考答案

相似：频繁的事交给硬件，OS 只在关键时刻出手；都靠特权指令、异常、陷阱表保护。不同：CPU 时分共享、内存空分共享；地址转换下硬件每次访存都要工作。

7. base/bounds 有什么缺陷？你会怎么改进？
参考答案

整个地址空间必须连续放，堆和栈中间没用到的空间也占着物理内存（内部碎片）。改进：代码、堆、栈分开放，每块一对 base/bounds，用虚拟地址的高几位选择用哪一对（分段）。

⚠️ 元层级薄弱点：今天第三次出现层级错误

  • 第一次：把 MMU 和 base、bounds 寄存器当成平级的三样东西（其实 base/bounds 是 MMU 的零件）
  • 第二次："靠虚拟化和异常防止进程乱来"，把第 3 层的目标和第 1 层的工具放在一起
  • 第三次："门运算"，问的是"做什么运算"，答到了最底层的电路
  • 和第 13 章是同一个问题：那次是把整体和组成部分颠倒、把 TLB 当成机制。这已经是跨章节反复出现的思维习惯，回答之前先问一句："问题问的是哪一层？"

本次学习中暴露的其他易错点

  • base = "空闲内存的起始地址"：应为"这个进程的地址空间在物理内存里的起始地址"
  • "先算物理地址再和界限比"：正文版本是先拿虚拟地址和 bounds（大小）比，再加 base
  • "计算之后再映射"：base + VA 这个加法本身就是映射，没有单独的一步
  • 以为静态重定位慢：它在装入时改一次，运行时不慢；问题是没保护、难搬家
  • 以为 4096 合法：条件是 VA < bounds，最后一个合法地址是 4095
  • 进程死亡时"清空寄存器"：真正要做的是把内存归还空闲列表
  • 从陷阱返回后"切回内核态"：应为用户态；内核态只有 OS 用
  • 搬家漏了"复制内存"：只改 base 不复制，新位置上什么都没有
  • "每个进程一对 base/bounds"：答的是现在的方案；分段后每个进程要三对
  • 粘贴答案三次（第 8 题计算、陷阱表、switch 时间线）：粘贴的 < 4096 当时没记住，换个问法就答错，说明关门输出必须自己掏
