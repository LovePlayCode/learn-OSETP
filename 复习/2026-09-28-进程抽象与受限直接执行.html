1本次复习覆盖的知识地图

进程三态转换（第4章）
├── 就绪 → 运行   触发：调度器的决定（搭便车在别的中断处理流程中完成，不是独立硬件中断）
├── 运行 → 就绪   触发：时钟中断（外部时钟硬件周期性强制打断）
├── 运行 → 阻塞   触发：陷阱 trap（进程自己发起系统调用，主动交权）
└── 阻塞 → 就绪   触发：设备中断（磁盘/网卡等外部设备完成任务后主动敲门）★本次新焊死

陷阱 vs 中断（第6章，"上下兄弟"关系）
        理念层：都是让 CPU 从当前代码跳进内核的机制
                        │
        ┌───────────────┴───────────────┐
   兄弟①：陷阱/异常                 兄弟②：中断
  （进程自己触发，同步的）        （外部硬件触发，异步的）
        │                              │
   例：系统调用、除零              例：时钟中断、设备中断

机制 / 策略跨领域迁移（第6章核心思想的验证）
  OS 内：机制=上下文切换/时钟中断；策略=调度算法
  缓存内：机制=链表节点增删；策略=LRU（选谁淘汰）
  打车软件：机制=派单执行流程（发单→接单→导航）；策略=派单规则（最近优先/评分优先）

Q1. 默画三态图，并标出每条箭头背后的触发机制A层
第一轮：四条箭头方向全对（09-23的老坑"阻塞→运行"写反，这次已完全修正），但完全没标机制。
第二轮：补充机制标注，但"就绪→运行"和"运行→就绪"标注成了完全相同的"时钟中断+上下文切换"——没有区分"被迫下台"和"被选中上台"的不同触发源。
第三轮：进一步补充，但把"设备中断"错认成了"陷阱回调"。
最终修正版（本次真正焊死）：
转换触发事件
就绪 → 运行调度器的决定（搭便车在中断处理流程中完成，不是独立硬件中断）
运行 → 就绪时钟中断
运行 → 阻塞陷阱（系统调用）
阻塞 → 就绪设备中断
本次新坑：把"设备中断"叫成"陷阱回调"——这是"陷阱/中断"这对兄弟第一次被记录混淆，此前三份存档均未出现过。
Q2. 陷阱 vs 中断，如何区分？新增
经过纠错后，学习者自己推导出正确区分：
· 陷阱/异常：进程自己主动或不小心触发（系统调用、除零），同步事件。
· 中断：外部硬件主动触发（时钟、设备完成I/O），异步事件，跟进程当前在做什么无关。
并且能自己说出"设备中断"这个具体名词——虽然没有直接背过，但通过"时钟中断是周期性无差别触发"这一特性做了合理类比推导。
提醒：曾一度联想到"轮询（polling）"，但该词不在已学笔记范围内，属于课外合理推测，不计入正式知识点，已当场澄清边界。
Q3. 举一个操作系统之外的机制/策略例子A层
第一轮：给出"时钟中断=机制，进程调度=策略"——被指出这只是笔记原句的同义替换，不算新例子。
第二轮：给出"LRU：删除节点是机制，怎么删除是策略"——概念方向反了，两句话其实说的是同一层。经引导修正为"LRU算法本身是策略，链表节点增删操作才是机制"——但LRU仍属于"资源淘汰选择题"家族，跟OS调度、页面置换是近亲，不算真正的新领域。
第三轮（通过）：打车软件——"把订单发给某位具体司机的执行流程"是机制，"该派给哪个司机"的决策规则是策略。这是第一次成功地把"机制/策略"框架完全脱离计算机领域、独立复述。
